# 4.泛型（条目26-33）列表


## 具体条目

    条目26： 不要使用原始类型
    看到 List 必须条件反射想到 List<?> 或 List<T>。原始类型只是为了兼容 Java 5 之前的代码而存在的。

    条目27： 消除Unchecked 类型的警告
    不要为了图省事在类上加 @SuppressWarnings("unchecked")。尽量缩小范围，加在局部变量或具体方法上，
    并在旁边加注释说明为什么这个强转是安全的。

    条目28： 列表优先于数组
    数组和泛型八字不合。数组在运行时检查类型，泛型在编译时擦除类型。两者混用（如 new T[] 或 
    new List<String>[10]）是不合法的。永远优先用 List<T>。

    条目29： 首选泛型类型
    如果你发现自己在写 Object 作为参数或返回值，停下来，思考能不能用泛型 <T> 替代。
    泛型方法配合类型推导，能让调用方写出极其简洁且安全的代码。

    条目30： 首选泛型方法

    条目31 (PECS 原则)：这是泛型最核心的实战技巧。
    往外拿数据（Producer）：<? extends T>
    往里塞数据（Consumer）：<? super T>
    既拿又塞：不要用通配符，直接用 <T>。

    条目31： 使用有限制的通配符增加API的灵活性
   

    条目32： 谨慎混用泛型和可变参数
     T... 底层是 Object[]，如果泛型被擦除，别人往里面塞错类型，编译器根本拦不住。
    除非你像上面那样做了严格的类型检查，否则加上 @SafeVarargs 时要格外小心。

    条目33： 考虑类型安全的异构容器  
    Class<T> 是一个极其强大的类型令牌（Type Token）。通过 Map<Class<?>, 
    Object> 配合 type.cast()，你可以实现一个能存放任意类型且取出时不需要强转的超级容器。
