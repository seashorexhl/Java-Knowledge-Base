# 1. 创建和销毁对象（条目1-9）

        何时和 如何创建对象，何时和如何避免创建对象，如何确保对象及时销毁，
    如何 管理在对象销毁之前必须进行的各种清理动作。

##  具体条目

    条目1：用静态工厂方法代替构造器
    静态工厂方法可命名、可缓存实例、可返回子类型，比构造器更灵活23。

    条目2：多参数构造时优先使用生成器（Builder）
    解决构造器参数过多时的可读性问题，避免“伸缩构造器反模式”3。

    条目3：利用私有构造器或枚举类型强化Singleton属性 用枚举实现单例 
    枚举单例是线程安全且防反射攻击的最佳实践，优于私有构造器方案38。

    条目4：利用私有构造器防止类被实例化
    工具类（全是静态方法）必须加 private 构造器，防止别人手滑 new 出来。

    条目5：优先考虑通过依赖注入来连接资源
    方法里需要什么资源（如数据库连接），通过参数传进来，不要在方法里 new，这样代码才方便做单元测试（Mock）。
    
    条目6：避免创建不必要的对象
    循环里不要 new 对象，字符串比较不要用 new String()，尽量复用不可变对象。
    
    条目7：清除过期的对象引用
    自己管理的集合/缓存，不用了要记得 remove() 或置为 null，否则 GC 也救不了你（内存泄漏）。

    条目8：避免使用终结方法和清理方法
    finalize() 性能极差且执行时机不确定。需要清理资源？实现 AutoCloseable 接口。

    条目9：try-with-resources 优于 try-finally
    只要涉及 IO、数据库连接、Socket 等，永远用 try (Resource r = ...) {}，
    告别又长又容易出错的 finally { r.close(); }。
