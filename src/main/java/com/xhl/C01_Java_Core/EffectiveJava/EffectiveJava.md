#  Effective Java 中文版 (第3版) 核心笔记

> **核心思想**：语法 + 词汇 + 用法 = 高效编程
> **目标**：编写出清晰、正确、健壮、灵活且易于维护的代码。

##  序言与背景

### 语言特性概览
- **核心范式**：面向对象、函数式、算法式
- **语言特性**：单继承、方法内部支持面向语句的命令式编程
- **标准类库**：提供丰富的数据结构、运算与功能支持
- **平台能力**：图形显示、网络、分布式计算、高安全性

### 版本演进与工具
- **Java 5**：引入泛型、枚举、注解、自动装箱、For-Each 循环、`java.util.concurrent` (JUC)
- **Java 7**：引入 `try-with-resources`、`@SafeVarargs` 注解
- **Java 8**：引入 Lambda 表达式、Stream 流、Optional 类、接口默认方法
- **Java 9**：引入 Module 模块化系统
- **开发工具**：IDE (Eclipse, IDEA, NetBeans)、静态分析工具 (FindBugs)

---

##  引言：核心概念与规范

- **API 范围**：`java.lang`, `java.util`, `java.io`, `java.util.function` 等
- **全书结构**：11 个章节，90 个条目
- **技术规范**：
    - **4种类型**：接口（含注解）、类（含枚举）、数组、基本类型
    - **类的对象**：类的实例和数组
    - **类的成员**：字段、方法、成员类、成员接口
    - **方法签名**：名称 + 形参类型列表
- **导出 API**：类、接口、构造器、成员、序列化形式

##  90条核心经验法则

### 1. 创建和销毁对象 (条目 1-9)
- **条目 1**：用静态工厂方法代替构造器（可命名、可缓存、可返回子类型）
- **条目 2**：遇到多个构造器参数时，优先使用构建器 (Builder)
- **条目 3**：用私有构造器或枚举类型强化 Singleton 属性（枚举是最佳实践）
- **条目 4**：通过私有构造器强化不可实例化的能力
- **条目 5**：优先考虑依赖注入来连接资源
- **条目 6**：避免创建不必要的对象
- **条目 7**：消除过期的对象引用（防止内存泄漏）
- **条目 8**：避免使用终结方法和清理方法 (`finalize`, `cleaner`)
- **条目 9**：`try-with-resources` 优先于 `try-finally`

### 2. 对于所有对象都通用的方法 (条目 10-14)
- **条目 10**：覆盖 `equals` 时请遵守通用约定
- **条目 11**：覆盖 `equals` 时总要覆盖 `hashCode`
- **条目 12**：始终要覆盖 `toString` 方法
- **条目 13**：谨慎地覆盖 `clone` 方法
- **条目 14**：考虑实现 `Comparable` 接口

### 3. 类和接口 (条目 15-25)
- **条目 15**：使类和成员的可访问性最小化
- **条目 16**：要在公有类中使用访问方法，而非公有域
- **条目 17**：使可变性最小化
- **条目 18**：复合优先于继承
- **条目 19**：要么设计继承并提供文档说明，要么禁止继承
- **条目 20**：接口优于抽象类
- **条目 21**：为后代设计接口（Java 8+ 默认方法）
- **条目 22**：接口只用于定义类型
- **条目 23**：类层次优于标签类
- **条目 24**：静态成员类优于非静态成员类
- **条目 25**：限制源文件为单个顶级类

### 4. 泛型 (条目 26-33)
- **条目 26**：不要使用原生态类型 (Raw Types)
- **条目 27**：消除非受检的警告 (Unchecked Warnings)
- **条目 28**：列表 (List) 优于数组
- **条目 29**：优先考虑泛型类型
- **条目 30**：优先考虑泛型方法
- **条目 31**：利用有限制通配符 (`? extends T`, `? super T`) 提升 API 灵活性
- **条目 32**：谨慎并用泛型和可变参数
- **条目 33**：优先考虑类型安全的异构容器

### 5. 枚举和注解 (条目 34-41)
- **条目 34**：用 `enum` 代替 `int` 常量
- **条目 35**：用实例域代替序数 (`ordinal`)
- **条目 36**：用 `EnumSet` 代替位域
- **条目 37**：用 `EnumMap` 代替序数索引
- **条目 38**：用接口模拟可扩展的枚举
- **条目 39**：注解优先于命名模式
- **条目 40**：坚持使用 `@Override` 注解
- **条目 41**：用标记接口定义类型

### 6. Lambda 和 Stream (条目 42-48)  *第3版重点*
- **条目 42**：Lambda 优先于匿名类
- **条目 43**：方法引用优先于 Lambda
- **条目 44**：坚持使用标准的函数接口 (`@FunctionalInterface`)
- **条目 45**：谨慎使用 Stream（保持代码可读性）
- **条目 46**：优先考虑流中无副作用的函数
- **条目 47**：优先使用 `Collection` 而不是 `Stream` 作为返回类型
- **条目 48**：谨慎使用 Stream 并行

### 7. 方法 (条目 49-56)
- **条目 49**：检查参数的有效性
- **条目 50**：必要时进行防御性拷贝
- **条目 51**：仔细设计方法签名
- **条目 52**：明智地使用重载
- **条目 53**：明智地使用可变参数
- **条目 54**：返回空集合或数组，而非 `null`
- **条目 55**：明智地返回 `Optional`
- **条目 56**：为所有公开的 API 元素编写文档注释

### 8. 通用编程 (条目 57-68)
- **条目 57**：将局部变量的作用域最小化
- **条目 58**：`for-each` 循环优先于传统的 `for` 循环
- **条目 59**：了解并使用类库
- **条目 60**：如果需要精确答案，避免使用 `float` 和 `double`
- **条目 61**：基本类型优先于装箱基本类型
- **条目 62**：如果其他类型更适合，尽量避免使用字符串
- **条目 63**：当心字符串连接引起的性能问题
- **条目 64**：通过接口引用对象
- **条目 65**：接口优先于反射机制
- **条目 66**：谨慎地使用本地方法 (Native Methods)
- **条目 67**：谨慎地进行优化
- **条目 68**：遵守普遍接受的命名惯例

### 9. 异常 (条目 69-77)
- **条目 69**：只针对异常的情况才使用异常
- **条目 70**：对可恢复的情况使用受检异常，对编程错误使用运行时异常
- **条目 71**：避免不必要地使用受检异常
- **条目 72**：优先使用标准的异常
- **条目 73**：抛出与抽象对应的异常
- **条目 74**：每个方法抛出的所有异常都要建立文档
- **条目 75**：在细节消息中包含失败-捕获信息
- **条目 76**：努力使失败保持原子性
- **条目 77**：不要忽略异常

### 10. 并发 (条目 78-84)
- **条目 78**：同步访问共享的可变数据
- **条目 79**：避免过度同步
- **条目 80**：`Executor`、`Task` 和 `Stream` 优先于线程
- **条目 81**：并发工具优先于 `wait` 和 `notify`
- **条目 82**：线程安全性的文档化
- **条目 83**：慎用延迟初始化
- **条目 84**：不要依赖于线程调度器

### 11. 序列化 (条目 85-90)
- **条目 85**：其他方法优先于 Java 序列化
- **条目 86**：谨慎地实现 `Serializable` 接口
- **条目 87**：考虑使用自定义的序列化形式
- **条目 88**：保护性地编写 `readObject` 方法
- **条目 89**：对于实例控制，枚举类型优先于 `readResolve`
- **条目 90**：考虑用序列化代理代替序列化实例
