# 2. 所有对象通用的方法（条目10-14）

    非final 方法都有明确的通用约定，任何 重写这些方法的类都有责任遵守其通用约定。 

## 具体条目
    
    条目10:在重写Equals 方法时要遵守通用约定
    不要自己写复杂的 if-else 判空逻辑，直接用 Objects.equals(a, b)，它内部已经帮你处理了 null 值。

    条目11:重写Equas方法时应该总是重写hashCode方法
    只要重写了 equals，就必须重写 hashCode。如果你只重写了 equals 而没重写 hashCode，
    两个逻辑上相等的对象放进 HashSet 会被当成两个不同的元素。

    条目12：总是重写 toString 方法
    在写业务代码时，强烈建议加上 @ToString (Lombok) 或者手动重写。否则在排查 Bug 时，
    日志里打印出 Product@1a2b3c 会让你怀疑人生。

    条目13：谨慎重写clone方法
    Cloneable 接口的设计本身就是一个历史遗留的败笔（它没有定义 clone 方法，只是作为一个标记接口）。
    拷贝对象时，拷贝构造器（Copy Constructor） 或 静态工厂（如 valueOf） 是更安全、更优雅的选择。

    条目14：考虑实现Comparable接口
    如果你实现了 Comparable，请确保 compareTo 返回 0 的情况与 equals 返回 true 的情况完全一致。
    否则在使用 TreeSet 或 TreeMap 时，会出现违反直觉的 Bug。另外，比较基本数据类型（如 double,int）时，
    一定要用包装类的 compare() 方法（如 Double.compare()），防止精度丢失或整数溢出。
