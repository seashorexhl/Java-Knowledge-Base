# UML（统一建模语言）

##  14 种图
        
###  UML 图及其核心用途

    1. 用例图（Use Case Diagram）
        核心作用：从用户（参与者）的角度出发，描述系统“能做什么”（功能需求）。它是需求分析阶段最常用的图。
        核心元素：参与者（小人）、用例（椭圆）、关系（关联、包含、扩展）。
        使用场景：向客户或产品经理确认系统功能边界，编写需求文档。
    2. 类图（Class Diagram）
        核心作用：描述系统的静态结构。展示类、接口及其相互关系（继承、实现、依赖、关联、聚合、组合）。它是面向对象设计的核心。
        核心元素：类名、属性、方法、各种关系箭头。
        使用场景：系统架构设计、数据库表结构设计的前置推导、指导代码编写。
    3. 时序图 / 顺序图（Sequence Diagram）
        核心作用：描述对象之间动态的交互过程，强调消息发送的时间顺序。
        核心元素：生命线（对象）、激活条、消息（同步、异步、返回）。
        使用场景：梳理复杂业务流程（如支付流程、登录鉴权）、排查接口调用链路、微服务交互设计。这是日常开发中使用频率最高的动态图。
    4. 状态图（State Machine Diagram）
        核心作用：描述一个对象在其生命周期内的所有可能状态，以及引起状态转移的事件和条件。
        核心元素：状态（圆角矩形）、转换（箭头）、触发事件、守卫条件。
        使用场景：设计具有复杂状态流转的业务实体，如：订单状态机（待支付->已支付->发货->完成/退款）、审批流程、工作流引擎。
    5. 活动图（Activity Diagram）
        核心作用：描述系统的业务逻辑和工作流，类似于高级的流程图。它支持并发、分支和循环。
        核心元素：动作节点、控制流、分支/合并、分叉/汇合（并发）。
        使用场景：梳理复杂的算法逻辑、跨部门的业务流程、后台定时任务执行逻辑。

    部署图（Deployment Diagram）：描述软件系统如何映射到硬件基础设施上（如：Nginx 部署在 A 服务器，Tomcat 部署在 B 服务器，Redis 集群部署在 C 节点）。运维和架构师必备。
    组件图（Component Diagram）：展示系统的物理组件（如 JAR 包、WAR 包、DLL）及其依赖关系。常用于大型系统的模块化拆分。
    包图（Package Diagram）：类图的宏观版本，展示代码包（Package）之间的依赖关系。常用于梳理大型项目的模块边界。
