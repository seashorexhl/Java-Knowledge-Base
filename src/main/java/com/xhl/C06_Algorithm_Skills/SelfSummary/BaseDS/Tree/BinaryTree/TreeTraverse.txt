一、 深度优先遍历（DFS）适用场景
    DFS 的核心特点是“一条路走到黑，不撞南墙不回头”，它倾向于尽可能深地探索分支。
 寻找所有可能的解（穷举与回溯）
    场景：迷宫问题、数独求解、N皇后问题、全排列、组合总和等。
    原因：DFS 天然适合递归和回溯算法。当走到死胡同时，可以方便地回退到上一个状态尝试其他分支，且只需记录当前路径的状态，内存开销小。
    判断连通性或寻找任意一条路径
    场景：判断图中两个节点是否连通、寻找迷宫的一条可行路径、拓扑排序、寻找强连通分量（Tarjan算法）。
    原因：如果只需要确认“是否存在”或找到“任意一条”满足条件的路径，DFS 往往比 BFS 更快，因为它不需要像 BFS 那样把周围所有的节点都遍历一遍。
 树/图的特定属性计算
    场景：计算树的深度、寻找二叉树的最近公共祖先（LCA）、二叉搜索树（BST）的中序遍历（获取有序序列）。
    原因：这些问题的本质需要“深入”到叶子节点后再向上回溯汇总信息，DFS 的递归特性完美契合这种自底向上的计算逻辑。
    内存受限且目标节点可能较深
    原因：DFS 的空间复杂度通常为 O(h)（h为树高或图的深度），而 BFS 为 O(w)（w为最大宽度）。在极度不平衡的树或图中，BFS 的队列可能会撑爆内存，而 DFS 依然游刃有余。
二、 广度优先遍历（BFS）适用场景
    BFS 的核心特点是“层层递进，像水波纹一样扩散”，它优先探索距离起点近的节点。
   寻找无权图/树的最短路径
    场景：社交网络中的最短好友链（如六度分隔理论）、迷宫的最短逃生路线、象棋中马跳到目标位置的最少步数。
    原因：BFS 保证了第一次访问到目标节点时，经历的层数一定是最少的。这是 BFS 最无可替代的优势，而 DFS 找到的路径通常不是最短的。
   按层级处理数据（层序遍历）
    场景：二叉树的层序遍历、按层打印二叉树、计算二叉树的宽度。
    原因：BFS 的队列机制天然保证了节点是按层级顺序被处理的。
   目标节点距离起点较近，且树/图极其宽广
    原因：如果目标就在起点附近，BFS 能迅速找到并结束搜索，避免了 DFS 深入错误分支带来的时间浪费。
   并行计算与网络爬虫
    场景：网页爬虫的抓取策略、P2P 网络中的节点发现。
    原因：BFS 的层级特性非常适合分布式并行处理，同一层的节点可以交由不同的机器同时处理。
三、选型建议
    如果题目要求“最短路径”、“最少步数”、“按层处理”，无脑选 BFS。
    如果题目要求“所有方案”、“是否存在”、“路径回溯”、“树的深度/祖先”，优先选 DFS。
